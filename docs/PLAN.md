# Memory Slot — план разработки расширения Firefox

**Что это.** Расширение для Firefox: пользователь включает его на нужном сайте → двойной щелчок по
слову или выделение фразы → перевод всплывает прямо над текстом → карточка сразу появляется в
плавающем окне → одним нажатием уходит в колоду и повторяется по интервальному алгоритму.

**Зафиксированные решения (12.09.2026):**

| Вопрос | Решение |
|---|---|
| Где работает | **нигде, пока пользователь сам не включит на сайте.** Включение — клик по иконке в панели браузера, права на сайт запрашиваются в этот же момент |
| Вызов | двойной щелчок по слову **или** выделение фразы. Никаких иконок-посредников, никаких режимов вызова |
| Показ перевода | подсказка над словом, исчезает сама при наведении на другой текст |
| Карточка | плавающее окно поверх страницы: закрывается, сворачивается, таскается мышью; стартует в правом верхнем углу |
| Провайдер перевода | ротация: Google gtx (неофициальный, без ключа) → MyMemory как запасной. Поле для своего ключа Google решено не делать (12.09), код провайдера оставлен |
| Язык интерфейса | только English |
| Хранилище карточек | только локально (IndexedDB) + экспорт/импорт JSON и CSV для Anki |
| Монетизация | бесплатно, донаты через поле Contributions на AMO |

**Главный принцип: элементарно и просто.** Каждая новая настройка и каждый лишний клик — это
минус к продукту. Если функцию можно не делать — не делаем.

---

## 1. Как это работает для пользователя

**Шаг 0. Включение на сайте.** По умолчанию расширение не работает нигде и не читает ни одной
страницы. Пользователь заходит на сайт, жмёт иконку Memory Slot в панели браузера и включает
тумблер **Enable on this site**. Firefox в этот момент спрашивает разрешение на доступ именно к
этому сайту. Дальше расширение помнит выбор: на этом домене оно активно всегда, пока его не
выключат тем же тумблером.

Иконка в панели всегда показывает состояние: активна на текущем сайте или нет.

**Шаг 1. Вызов.** На включённом сайте — либо двойной щелчок по слову (браузер сам выделяет слово),
либо протягивание мышью по фразе. Больше ничего нажимать не нужно.

**Шаг 2. Подсказка над текстом.** Мгновенно, над выделением, появляется маленькая плашка с
переводом. Она эфемерная: исчезает, как только мышь пошла на другой текст, при скролле, при клике
мимо и по Esc. Ничего не нажимаем, чтобы её убрать.

**Шаг 3. Карточка в окне.** Одновременно в плавающем окне в правом верхнем углу появляется полная
карточка: оригинал, перевод, язык источника, предложение-контекст, озвучка, кнопка
**Add to deck**. Окно не перекрывает то место, где пользователь читает, и живёт своей жизнью.

**Шаг 4. Окно.** Его можно перетащить за заголовок в любое место страницы, свернуть в узкую
полоску (остаётся счётчик карточек за сегодня) и закрыть крестиком. Положение и состояние
запоминаются и восстанавливаются на всех страницах и после перезапуска браузера. Закрытое окно
возвращается при следующем переводе.

Это весь основной сценарий. После однократного включения на сайте он должен работать без единого
обращения к настройкам.

### Что ещё входит в v1.0

- Настройки: целевой язык, язык источника (auto / фиксированный), свой API-ключ, **список сайтов,
  где расширение включено** (с возможностью выключить любой), тема. Всё на одной короткой странице.
- Менеджер карточек: список, поиск, правка, удаление, экспорт/импорт.
- Режим повторения: сессия SM-2, управление с клавиатуры.
- Popup в панели браузера: тумблер сайта, сколько карточек к повторению сегодня, кнопка Review,
  ссылка Support.

### Чего в v1 сознательно нет

Синхронизация между устройствами, аккаунты, картинки в карточках, перевод всей страницы,
поддержка PDF-просмотрщика и canvas-редакторов, мобильный Firefox, Chrome-сборка,
альтернативные способы вызова (горячие клавиши, наведение, кнопки).

## 2. Технологический выбор

- **Manifest V3 для Firefox.** Фон — событийная страница (`background.scripts`), а не service
  worker: в Firefox MV3 это штатный путь, работает с promise-API `browser.*`.
- **`browser_specific_settings.gecko.id`** задать сразу — без него storage не переживёт
  переустановку, и AMO не примет обновление.
- **TypeScript + esbuild**, вывод **без минификации**. Минифицированный бандл на AMO требует
  отдельной подачи исходников и удлиняет ревью; несжатый снимает вопрос.
- **Без UI-фреймворка.** И подсказка, и окно живут в Shadow DOM на vanilla — иначе CSS сайта
  покалечит вёрстку. Страницы popup/options/manager/review тоже vanilla.
- **Тесты:** vitest на чистую логику (парсер gtx, SM-2, хранилище), `web-ext run` для ручного
  прогона по матрице сайтов.

## 3. Архитектура

```
src/
  content/
    trigger.ts        // dblclick по слову + выделение фразы, фильтры, антидребезг
    tooltip.ts        // эфемерная плашка над текстом (Shadow DOM)
    panel.ts          // плавающее окно: drag, minimize, close, restore (Shadow DOM)
    panel-state.ts    // позиция и состояние окна в storage.local
    styles.css        // инлайнится в shadow root
  background/
    index.ts          // роутер сообщений
    site-gate.ts      // права по требованию, регистрация скрипта, состояние иконки
    translate.ts      // оркестрация: кэш -> лимитер -> провайдер -> fallback
  lib/
    providers/
      types.ts        // interface TranslationProvider
      google-gtx.ts   // translate.googleapis.com/translate_a/single?client=gtx
      google-cloud.ts // translation.googleapis.com/language/translate/v2 (ключ пользователя)
    store/
      db.ts           // IndexedDB: cards, decks, reviews
      settings.ts     // browser.storage.local
      export.ts       // JSON / CSV(Anki)
    srs/sm2.ts        // интервальные повторения
    langs.ts          // языки и коды
  pages/
    popup/  options/  manager/  review/
  _locales/en/messages.json
```

**Правило номер один: весь сетевой трафик только из фона.** Из контентного скрипта запрос упрётся
в CSP страницы и CORS, причём по-разному на разных сайтах. Контент шлёт
`runtime.sendMessage({type:'translate', ...})` и ждёт ответ.

### Включение по сайтам и права по требованию

Это не просто настройка, а несущая конструкция: контентный скрипт **не объявлен в манифесте
вообще** и физически не может выполниться на сайте, который пользователь не включил.

1. В манифесте вместо `content_scripts` — `optional_host_permissions: ["<all_urls>"]` и
   права `scripting`. При установке расширение не просит доступа ни к одному сайту — только к
   двум своим API-хостам.
2. Клик по иконке открывает popup с тумблером. Включение вызывает
   `browser.permissions.request({ origins: ['https://example.com/*'] })` — это обязательно
   происходит в обработчике клика на странице расширения, иначе Firefox запрос отклонит.
3. После выдачи прав `site-gate.ts` регистрирует контентный скрипт для этого origin через
   `browser.scripting.registerContentScripts({ persistAcrossSessions: true, allFrames: true })`.
4. Зарегистрированный скрипт начинает работать со следующей навигации, поэтому текущую вкладку
   дополнительно оживляем разовым `browser.scripting.executeScript` — иначе пользователь включит
   тумблер и решит, что ничего не произошло.
5. Выключение: `permissions.remove` + `unregisterContentScripts`. Уже открытые вкладки этого сайта
   гасим сообщением — контент снимает обработчики и убирает окно.
6. Источник правды — сам факт наличия права (`permissions.contains`), а не запись в storage:
   пользователь может отозвать доступ через «Управление расширениями» мимо нашего UI.
   Подписываемся на `permissions.onAdded` / `onRemoved` и приводим регистрацию в соответствие.
7. Состояние в панели: **бейдж `ON`** на иконке, когда контентный скрипт доложил о себе
   сообщением `content-ready`; на `tabs.onUpdated` со статусом `loading` бейдж гасится. Статус
   виден без открытия popup и, что важнее, без права `tabs`: адрес вкладки узнавать не нужно
   вообще — сам факт появления скрипта и есть ответ.

   Бейдж, а не вторая иконка: `action.setIcon` принимает путь к SVG, возвращает успех и не
   перерисовывает кнопку. Проверено вживую 12.09 — ни исключения, ни ошибки в консоли, просто
   ничего не происходит. Бейдж рисует сам Firefox, от формата картинки он не зависит, и заметен
   он лучше, чем оттенок серого.

Гранулярность — по origin (схема + домен), то есть «включено на reddit.com» целиком, без
разбирательства по путям. Это просто и понятно; поддоменные тонкости в v1 не трогаем.

Что это даёт, помимо выполнения требования:

- При установке расширение не просит **никаких** прав — самая низкая планка входа, какая бывает.
- Ревью на AMO проходит заметно мягче: `<all_urls>` в `content_scripts` — главный красный флаг.
- Честный ответ на вопрос о приватности: на сайтах, которые вы не включили, расширение не читает
  ни строчки и никуда ничего не отправляет.

### Триггер: двойной щелчок и выделение

Два события дают одно и то же выделение, и если не развести их, всё сработает дважды:

- `dblclick` → браузер уже выделил слово, берём `window.getSelection()`.
- `mouseup` → выделение фразы; обрабатываем, только если текст непустой **и** прошло больше
  ~300 мс после последнего `dblclick` (иначе поймаем хвост двойного щелчка).

Фильтры, без которых расширение будет мешать: не срабатываем в `input`, `textarea` и
`contenteditable` (человек редактирует текст, а не читает); игнорируем выделения длиннее ~200
символов и чисто числовые. Не реагируем на клик по ссылке — пусть переход отработает нормально.

### Подсказка над текстом

Якорь — `Range.getBoundingClientRect()` выделения. Плашка ставится над верхней границей; если
сверху не помещается — переворачивается вниз. Ширина ограничена, длинный перевод переносится.

Жизненный цикл — только автоматический, никаких кнопок закрытия:
`mouseover` по тексту вне якоря → скрыть; `scroll`/`resize` → скрыть; `Esc` → скрыть;
новое выделение → заменить содержимое. Небольшая задержка ~150 мс перед скрытием, чтобы плашка не
мигала от дрожания мыши.

Пока перевод грузится — в плашке точечный индикатор, а не пустота.

### Плавающее окно

- Хост-элемент вешается на `document.documentElement`, а не в `body`: часть сайтов переписывает
  body целиком. `position: fixed`, `z-index: 2147483647`, внутри Shadow DOM с `all: initial`.
- Некоторые сайты ставят свои оверлеи с тем же z-index. Проверяем через `MutationObserver`, что
  наш хост остался последним ребёнком, и при необходимости переставляем.
- Полноэкранный режим: `fixed`-элемент пропадает, когда страница уходит в fullscreen. Ловим
  `fullscreenchange` и переносим хост внутрь полноэкранного элемента.
- Перетаскивание: `pointerdown` на заголовке → `setPointerCapture` → `pointermove` двигает окно,
  позиция клампится в границы viewport. При ресайзе окна браузера окно не должно уехать за экран.
- Состояние `{x, y, minimized, closed}` пишется в `storage.local` (с троттлингом при драге) и
  читается при инициализации на каждой странице. Стартовое положение: правый верхний угол,
  отступ 16 px.
- Свёрнутое состояние — полоска высотой в заголовок со счётчиком «N due today».
- Закрытие — только скрытие; следующий перевод показывает окно снова на том же месте.

### Модель данных

```ts
type Card = {
  id: string
  front: string            // selected text
  back: string             // translation
  langFrom: string         // detected or forced
  langTo: string
  context?: string         // sentence around the selection
  sourceUrl?: string
  sourceTitle?: string
  deckId: string
  tags: string[]
  createdAt: number
  srs: {
    state: 'new' | 'learning' | 'review' | 'relearning'
    ease: number           // starts at 2.5
    interval: number       // days
    due: number            // timestamp
    reps: number
    lapses: number
  }
}
```

Индексы IndexedDB: `due` (выборка сессии), `front+langTo` (защита от дублей), `deckId`, `createdAt`.

### Слой провайдеров

```ts
interface TranslationProvider {
  id: string
  translate(req: { text: string; from: string | 'auto'; to: string }):
    Promise<{ text: string; detectedFrom?: string; alternatives?: string[] }>
}
```

Оркестратор: `normalize(text)` → `LRU-кэш (500 записей, TTL 7 дней)` → `лимитер (не чаще
1 запроса / 300 мс, не больше 60 / мин)` → провайдер → при `429/403`/сетевой ошибке
экспоненциальный backoff, затем резервный провайдер, затем честная ошибка в подсказке.

**Кэш — не оптимизация, а условие выживания.** Двойной щелчок — дешёвый жест, кликать будут часто;
без кэша и лимитера gtx закроется по частоте запросов за день.

### Ротация провайдеров (реализовано 12.09)

Практика подтвердила риск из таблицы ниже: gtx отдаёт `HTTP 429` по IP уже при обычном тестовом
использовании. Поэтому:

1. Провайдеры опрашиваются по очереди: свой ключ (если есть) → gtx → MyMemory.
2. У **каждого** провайдера своя пауза после отказа: 60 с, дальше удвоение до 15 минут, сброс при
   первом успешном ответе. Пауза лежит в `storage.local` — событийная страница выгружается.
3. Отказавший провайдер пропускается, запрос уходит следующему. Сообщение об ошибке пользователь
   видит, только когда отказались все, и в нём стоит наименьшее оставшееся время.
4. Обрыв сети паузу **не** начисляет: это сеть пользователя, а не вина провайдера, иначе мы
   заблокировали бы разом всех.
5. MyMemory не определяет язык источника сам, поэтому при `auto` язык определяется
   `browser.i18n.detectLanguage` — без сети и без дополнительных прав.

Lingva и LibreTranslate рассмотрены и отклонены: публичные зеркала держат волонтёры, они
исчезают, а каждое — это ещё одна компания, получающая текст пользователя, и ещё один хост в
манифесте.

## 4. Права доступа

```jsonc
"permissions": ["storage", "scripting", "activeTab"],
"optional_host_permissions": ["<all_urls>"],
"host_permissions": [
  "https://translate.googleapis.com/*",
  "https://translation.googleapis.com/*"
],
"action": { "default_popup": "popup.html" }
```

Плюс обязательная декларация в `browser_specific_settings.gecko`:

```jsonc
"data_collection_permissions": { "required": ["websiteContent"] }
```

Mozilla делает этот ключ обязательным, и заявлять нужно честно: выделенный текст уходит с
устройства в Google. Ключ поддерживается с Firefox 140 (142 на Android) — отсюда
`strict_min_version: "140.0"`, которая заодно совпадает с текущей ESR-линейкой.

Секции `content_scripts` нет вообще — скрипт регистрируется из кода только для включённых сайтов.
Ни `tabs`, ни `webRequest`, ни `unlimitedStorage`.

`activeTab` вместо `tabs`: попапу нужен адрес текущей вкладки, чтобы назвать сайт и запросить
права именно на него. `activeTab` даёт это только пока попап открыт и только для вкладки, которую
пользователь сам выбрал, нажав на иконку. Право `tabs` дало бы адреса всех вкладок всегда —
несоразмерная цена за одну строчку в интерфейсе.

Два хоста провайдеров оставлены обязательными: без них расширение бессмысленно, а дополнительный
запрос прав при первом же переводе пугает сильнее, чем строчка при установке. Это единственное,
что расширение просит при установке; доступа к сайтам пользователя оно при этом не получает.

## 5. Этапы

### M0 — Каркас (0.5 дня)
Репозиторий, `package.json`, esbuild, `manifest.json`, `web-ext`, ESLint + Prettier,
CI (lint + test + `web-ext lint`).
**Готово, когда:** `npm run dev` поднимает Firefox с расширением, иконка на панели живая.

### M1 — Ядро перевода (1–1.5 дня)
Провайдеры, gtx, кэш, лимитер, ошибки, юнит-тесты на разбор ответа gtx (формат вложенных
массивов недокументирован и легко ломается).
**Готово, когда:** `translate('hello','auto','uk')` из фоновой консоли отдаёт «привіт», повторный
вызов не идёт в сеть, при обрыве сети возвращается типизированная ошибка.

### M2 — Включение по сайтам (1–1.5 дня) — делаем рано, это каркас всего контентного слоя
Popup с тумблером, `permissions.request` из обработчика клика, динамическая регистрация и снятие
контентного скрипта, оживление текущей вкладки, реакция на внешний отзыв прав, состояние иконки и
бейдж, список включённых сайтов.
**Готово, когда:** свежеустановленное расширение не просит доступа ни к одному сайту
пользователя (только два наших API-хоста); на невключённом сайте в
`document` нет ни одного нашего элемента и ни одного обработчика; включение работает на текущей
вкладке сразу, без перезагрузки; отзыв прав через «Управление расширениями» гасит расширение на
сайте без перезапуска браузера.

### M3 — Триггер и подсказка над текстом (1.5–2 дня)
Двойной щелчок и выделение с разведением событий, фильтры полей ввода и ссылок, якорь по
`getBoundingClientRect`, переворот вниз при нехватке места, автоскрытие по наведению/скроллу/Esc,
индикатор загрузки.
**Готово, когда:** на матрице сайтов (Wikipedia, Reddit, GitHub, YouTube, Gmail, новостной сайт с
агрессивным CSS, сайт с тёмной темой) подсказка встаёт точно над словом, не мигает и не мешает
выделять текст как обычно.

### M4 — Плавающее окно (2 дня)
Хост в `documentElement`, Shadow DOM, drag за заголовок с клампом, minimize, close, сохранение и
восстановление позиции, защита z-index через `MutationObserver`, перенос в fullscreen-элемент,
поведение при ресайзе окна браузера.
**Готово, когда:** окно перетащено в левый нижний угол, свёрнуто, страница перезагружена и открыта
другая — окно вернулось туда же и в том же состоянии; на YouTube в полноэкранном режиме оно видно.

### M5 — Хранилище и карточки (1.5 дня)
IndexedDB, схема, миграции, `Add to deck` с подхватом предложения-контекста, URL и заголовка,
дедупликация, подтверждение с Undo.
**Готово, когда:** карточка переживает перезапуск браузера, повтор того же слова предлагает
обновить существующую вместо дубля.

### M6 — Настройки (0.5–1 день)
Одна короткая страница: целевой язык с поиском, источник auto/фиксированный, свой API-ключ с
кнопкой проверки, список включённых сайтов с выключением, тема, ссылка Support. Применение на лету.
**Готово, когда:** смена целевого языка немедленно меняет результат на уже открытой вкладке;
выключение сайта из списка гасит его так же, как тумблер в popup.

### M7 — Менеджер и экспорт (1.5 дня)
Таблица карточек, поиск, инлайн-правка, массовое удаление, колоды, экспорт JSON (полный, с
состоянием SRS) и CSV/TSV для Anki, импорт JSON с проверкой схемы.
**Готово, когда:** экспорт → чистый профиль → импорт восстанавливает колоду и расписание один в один.

### M8 — Режим повторения (1.5 дня)
Сессия SM-2: front → Space открывает back → 1/2/3/4 = Again/Hard/Good/Easy, лимиты новых и
повторов в день, статистика недели в popup.
**Готово, когда:** юнит-тесты sm2 дают ожидаемые интервалы, включая lapse и переучивание.

### M9 — Полировка и приватность (1 день)
Онбординг при первом запуске: одна страница, которая объясняет, что расширение выключено везде и
включается иконкой в панели, плюс прямой текст «selected text is sent to Google for translation».
Понятные сообщения об ошибках провайдера, доступность (фокус, ARIA, работа с клавиатуры),
`prefers-reduced-motion`, иконки 16/32/48/96/128 в двух состояниях.

### M10 — Публикация (0.5 дня)
`web-ext lint` в ноль, `web-ext build`, листинг на AMO: описание EN, скриншоты, privacy policy,
поле Contributions, changelog, тег версии.

**Итого:** порядка 12–14 рабочих дней до публикации v1.0.

## 6. Донаты

- Основной канал — поле **Contributions** в листинге AMO (Ko-fi, Patreon, Liberapay,
  GitHub Sponsors, PayPal.me, micropayme; ссылка одна, менять можно).
- В расширении — **одна** сдержанная ссылка Support внизу popup и в настройках.
- Политика AMO запрещает навязчивые просьбы: всплывающие напоминания, баннеры и блокировка
  функций до оплаты — отказ в ревью. В подсказку и в окно карточки ничего не ставим.
- Платных функций нет: иначе теряется смысл заявленного «бесплатно».

## 7. Риски и что с ними делать

| Риск | Насколько реально | Ответ |
|---|---|---|
| Пользователь не понял, что надо включить сайт, и решил, что расширение сломано | **Высоко — главный риск продукта** | Онбординг сразу после установки + подсказка от иконки при первом заходе; приглушённый значок явно отличается от активного |
| gtx отдаёт 429 или капчу | Высоко: двойной щелчок — частый жест | Кэш + лимитер + backoff; при исчерпании честное сообщение и предложение вписать свой ключ |
| Google меняет формат ответа gtx | Средне, раз в год-два | Парсер изолирован в одном файле, тесты на зафиксированных образцах ответа |
| Динамическая регистрация скрипта рассинхронизировалась с правами | Средне | Источник правды — `permissions.contains`, сверка при старте фона и по `permissions.onAdded/onRemoved` |
| Двойной щелчок конфликтует с сайтом | Высоко: многие сайты вешают свой `dblclick` | Свои обработчики в фазе всплытия и без `preventDefault` — родное поведение сайта не ломаем |
| Сайт перекрывает окно своим оверлеем | Средне | Хост в `documentElement`, максимальный z-index, `MutationObserver` возвращает хост наверх |
| Окно пропадает в полноэкранном видео | Точно | Перенос хоста в fullscreen-элемент по `fullscreenchange` |
| Вёрстка ломается на конкретном сайте | Высоко | Shadow DOM с `all: initial`, матрица сайтов в M3 и M4 |
| Вопросы на ревью AMO по неофициальному endpoint | Средне | Хосты объявлены честно, код не обфусцирован, назначение запроса описано в заметке ревьюеру |
| Приватность: текст уходит третьей стороне | Факт | Privacy policy + онбординг; на невключённых сайтах расширение не читает ничего вообще |

## 8. Известные ограничения v1 (честно вынести в описание на AMO)

- Расширение выключено по умолчанию и включается на каждом сайте отдельно — это сделано намеренно.
- Нет синхронизации между устройствами — карточки живут в профиле браузера. Бэкап = экспорт.
- Не работает там, где нет обычного DOM-выделения: PDF-просмотрщик, Google Docs, Figma.
- Не срабатывает в полях ввода — чтобы не мешать печатать.
- Качество перевода = качество Google, оффлайн-режима нет.
- Firefox для Android в v1 не проверяется.
